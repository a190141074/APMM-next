# 架构与不变量

```text
src-ui/app                 外壳、导航、主题与页面生命周期
src-ui/modules             资源页、详情、导入导出、插件、设置、任务中心
src-ui/hooks               查询、错误反馈、订阅、启动检查
src-ui/core/domain         资源分组、筛选、任务修订号、分卷去重
src-ui/core/services        新服务和旧命令适配
src-ui/core/ipc             原生传输、演示数据、命令常量、Rust 生成 DTO
src-tauri/src              Rust 命令、领域状态与兼容实现
plugins/asset-tool          独立资产工具源码、测试和依赖
config                     分类、渠道、公钥、名称元数据
tools                      构建、生成、隔离验收与产物审计
```

## 状态所有权

资源与设置只有 `Library` 一份持久状态。前端 React Query 保存查询快照；任务有修订号，迟到的轮询不能覆盖更新的事件。任务管理器不随页面卸载；一个有界写入通道协调扫描、下载、提取、插件和更新。取消在检查点执行，最终提交区间禁用取消。

任务快照和可恢复参数持久化到 `data/tasks/history.json`，保留最近 200 项。重启时排队/运行状态转成可诊断的中断状态。密码不写入历史；依赖内存队列的包提交需重新打开导入窗口。

资源模型明确分离 `fullName`、`applicationSlot`、`groupKey` 和 `ModFile.hash/path`。已知官方完整变体不做文件名归一丢弃；同槽位三个文件具有三个独立哈希和 Vault 路径。地块仅按相同数字 ID 分组，鼠标两种状态分组；分组不合并实际文件。临时资源没有有效应用槽位，支持收藏、启禁、导出和后续重新分类。

## 写入与兼容

`resource_transaction` 先备份游戏中相关文件，再提交整组及库索引；任何一步失败回滚。`migration_journal` 为复制迁移提供跨进程恢复。预设、包导入、工坊和 APX 保留专门的事务语义，不因为表面相似而共用有差异的规则。

历史命令在 `lib.rs` 注册，`legacy_commands`、`resource_mutation`、`packages` 等保留协议适配。新页面通过集中常量调用。新 DTO 从 `dto.rs` 导出，生成目录禁止手改；遗留 JSON 载荷仍是渐进迁移边界。

## 下载、插件与更新

`downloads` 以资源身份、摘要和大小生成缓存键；限制并发，验证完整 Content-Range，200 响应重新开始，206 范围不正确拒绝拼接。支持来源重试/降级、速度反馈、已验证缓存和取消续传。连接和单次读取有超时边界。未通过大小和 SHA-256 的缓存不交给安装器。

辅助插件验证 Ed25519 清单、版本范围、全部文件大小/摘要和受控下载来源。运行持有版本锁，更新等待运行结束后切换 current 指针。安装失败不改变当前指针。卸载仅处理签名清单拥有的文件，提取成果在 `data/assets` 独立保留。旧版本目录可用于诊断，未做用户数据递归清除。

便携软件更新仅操作 `portable_update::ALLOWED` 和发行清单共同允许的文件。下载校验后等待任务通道与库锁，助手备份、整批替换、启动新版并等待工作区确认；失败回滚。更新日志和下次启动恢复不能依赖当前页面。

## 原图与资产工具

优先使用校验有效的本地产物，其次远端预览缓存，最后显示缺图。官方原图和缩略图不共用可变文件。资产插件未安装不妨碍 Mod 管理。

分类定义由 `config/sections.json` 单向生成到 Python 包。Addressables 和内置资源共用像素输出和事务；无类型树的 cursor 资源使用 Unity 2022.3 系列经当前样本验证的最小 Texture2D 描述，遇到未知版本明确失败。RGBA、原尺寸、透明边和完整资源名称保留，不拼图。

JSON 单结果接口保留；JSONL 使用 `protocol: 1` 的进度/结果事件，标准输入接受取消。目录/依赖/内置资源及解码版本参与增量指纹，单张提取不标记整个分类已同步。预算是解码资源预算，不等于进程内存硬上限。

## 发行边界

主 ZIP 仅有程序、助手、必要 DLL、发行清单和许可文本。插件 ZIP 单独携带 EXE/Python 运行依赖，不含现成游戏数据。参考图片仅供本机浏览器 QA，经 Vite 开发中间件读取，不进入前端构建。

## 工坊与离线作者流程

总览的 `SocialMedia` 默认完整展示四个入口，`compact` 参数保留折叠版备用。关于内容延迟加载到设置，作者模式开关位于“设置 → 工坊”。`App` 根据持久开关显示投稿导航，草稿会话串行保存；切换页面只改变展示，不取消已创建的后台任务。

`OverviewVersions` 读取当前程序版本，并与 APX 页面共用 `plugin_status` 查询和失效通知，不维护第二份安装状态。`usePageReveal` 只为当前页新节点播放有界逐项动画；节点轮询复用不会重播，虚拟资源列表仅首批播放。页面卸载与减少动画设置取消动画，基础样式始终可见。

卡面默认直接列表，其他分类默认卡片，各分类的布局选择单独保存在本机界面偏好。`ResourceList` 按资源部位展开并虚拟化；`ResourceCandidateRow` 和 `useResourceActions` 同时服务列表与原详情，保留具体候选哈希、比较、管理、应用和整组操作的边界。布局切换只改变可见节点位置和透明度，绝不写资源库或游戏。

目录来自固定静态来源并验证发布者签名。v2 在同一响应中包含签名与载荷；仅 404 回退到旧 v1。目录读取不等待封面下载。获取先返回绑定作品和本地状态的预检计划，提交前再次验证，默认只加入库；应用必须指定唯一候选，复用既有备份与库事务。

作者流程默认无服务器：本地来源 → 原始字节 blob → 草稿 → 不可变快照 → 离线投稿 ZIP。快照和导出不创建系统凭证；记录只标记已导出，不推断已交稿或已发布。导入投稿包只能恢复到空白草稿，已发布修订必须来自受信签名目录，不能信任包自报身份或修订。

维护者在本机 `inspect`，填写实际资源/游戏审核和原收稿渠道的身份依据，再 `prepare` 到新目录。只有 `workshop/` 是公共产物，审核资料留在 `private/`。`check-base` 防止旧准备目录覆盖期间新增作品；Git 提交、推送和收稿通信由维护者明确执行。公开摘要复核成功才产生确认记录。部署 HTTP 服务不是这一流程的前提，已有可选服务保持关闭。
