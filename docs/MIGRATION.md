# 旧版数据迁移与恢复

1. 将新版 ZIP 解压到新目录，保留旧版目录；运行 `astral-mod-manager.exe`。
2. 首次向导或“设置 → 旧库迁移”选择旧版 **data 目录**，该目录必须含 `library.json`。
3. 核对 Mod 数量、文件数、占用和目标。关闭旧版后确认复制。
4. 迁移任务进入任务中心。新版资源库非空时拒绝覆盖，请改用包导入。
5. 完成后单独核验游戏目录。迁移保留应用记录，但不会重新写入游戏。

复制包括 Vault、资源索引、预设、设置、工坊归属和预览缓存。历史绝对路径只按目录边界重写，其他路径不误替换；日志、更新暂存、任务历史和已安装辅助插件不从旧目录复制。系统凭据默认密码沿用原服务键名，不导出为普通文件。

复制每个文件前后检查 SHA-256，全部复制完成后再次核对源目录清单和摘要。源发生修改时放弃本次提交，可关闭旧版后重试。源目录始终只读。

提交前，`migration-pending.json` 保存目标、暂存、备份和每个已计划文件的前后摘要。载荷先发布、`library.json` 后发布、完成标记最后发布。程序异常退出后，下次启动读取日志并恢复旧目标；用户在中断后外部修改的文件会阻止自动覆盖，保留 B 盘备份供核对。正常取消也走同一恢复逻辑。

恢复失败时查看便携目录 `data/logs` 和 `data/migration-pending.json` 中的备份位置。不要删除恢复记录或备份，也不要用旧工程根作为临时目录。恢复到可重试状态后重新启动迁移，不需要修改旧库。

历史 APMMOD01/02/03、无 `storageName` 的旧包、同槽位多个文件继续走兼容解包与唯一 Vault 路径分配。多分卷只添加其中一个入口即可，缺少其余分卷会明确失败；密码错误不提交文件。导入预览的选项决定“仅加入库”还是应用，不根据图片选中状态自动应用。

## 0.3.39 管理字段兼容

旧预设保留 ID、名称和字符串哈希，缺少范围时作为全局预设读取，缺少锁定字段时默认未锁定。空哈希表示原版，恢复原版只清除替换文件，无需提前提取原图。局部预设的保存项就是固定作用范围；移除项目同时缩小范围。候选编辑、删除或重新归类不改写预设，旧哈希和显示名称保留，用户在预设页明确修复后再应用。

旧预设将鼠标、地块、卡面等候选的分类记为 `heroes` 库容器。预览和应用只在完整名称、对象、部位均一致时解析实际分类，原预设记录保持原样；身份不一致仍作为无效槽位汇总，不能自动猜测修复。

旧候选缺少 `info`、`classification` 和 `fsIdentity` 时使用兼容默认值；信息按槽位与哈希独立保存，文件标识由下一次扫描补充。作者、HTTPS 来源和版本随 apmod 的可选 `provenance` 字段传递，本机备注不进入包；重复导入只补空字段。手动归属通过可选 `manualClassification` 保留，旧包缺少这些字段仍正常导入。

`provenance` 新增可选画师 `artist`、作者链接 `authorUrls` 和画师链接 `artistUrls`，旧数据缺少时分别为空字符串和空列表。链接支持多项，保存与打开仍限定 HTTPS；作者、画师和链接随包分享，本机已有非空信息或链接列表优先保留。候选显示名称允许中文、空格和符号，只编辑记录；编辑框隐藏 PNG 后缀，导出图片会单独构造有效 PNG 文件名，不能将显示名称当 Vault 路径。

目录监听默认开启。旧设置缺少 `monitorDirectories` 时保持此默认值，也可以在设置页关闭。后台同步只读取游戏文件并更新库，清理和迁移仍是独立入口。`externalBindings` 和规则确认记录防止重复扫描生成临时副本或撤销已确认归属；外部临时启禁状态变化只同步库副本，同一外部状态不会反复覆盖本机启禁选择。
