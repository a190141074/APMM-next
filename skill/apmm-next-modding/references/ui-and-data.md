# 已确认的界面与数据约定

此基线整理于 2026-11-15，服务于保持后续修改一致；用户的新要求可以改变设计。涉及实现时先核对下面列出的当前文件，而不是把历史截图当作不可修改的模板。

## 界面与导航

- 启动时先读本地预览缓存；存在缺失图片时提供“是 / 否 / 不再提醒”。“是”复用预览下载任务，“否”只关闭本次提示，“不再提醒”持久化在工作区设置；设置页可重新开启并保留手动下载入口。缓存完整时不弹窗；欢迎向导结束后再检查，预览任务终态后刷新缓存状态。
- outimg 定位是对应部位卡右侧的醒目竖向按钮，不覆盖原版缩略图或应用入口；列表与详情共用布局，窄窗仍可见。原版缩略图只在对应 outimg 文件实际存在时显示定位按钮。

- 更新检查间隔使用分钟输入与调度，支持一分钟；旧小时设置先按原时长换算。验收必须覆盖保存后重进、真实计时触发及关闭后的取消，不只更换文案单位。

- 用户既包括 Mod 作者，也包括使用者。文案围绕管理、应用、分享和当前状态，不默认把所有人当作者，不添加占据空间的宣传或教学块。
- 资源页使用紧凑标题和筛选工具栏，把空间留给图片；窄窗口允许筛选自然换行。预览尺寸按“特小、小、中、标准、大、特大”六档显示，值为 tiny/small/medium/standard/large/xlarge；尺寸展开面板右侧放竖向“统一大小”复选框，默认勾选。统一模式读写全局档位，关闭后恢复各板块独立偏好，重新统一不得覆盖独立值。列表和详情共用入口及尺寸定义，同步卡片、候选列表、详情图片与虚拟行高；窄窗允许一列，不能重叠或留下额外行间空隙。
- 侧栏应用分组保留设置入口；“关于”和“作者模式”开关位于设置内部，不能按旧截图恢复独立关于导航或标题栏作者开关。设置使用顶部横向分区，默认“目录与资源”；顺序为目录与资源、外观、配色、工坊、更新、安全与维护、关于。名称“角色地块”“鼠标样式”“临时资源”分别改为“地块”“鼠标”“临时”。
- 任务入口位于主题切换按钮旁，使用向下展开的 Radix 卡片浮窗 `TaskPopover`。进度、活动计数、暂停、继续、重试、取消及终态结果仍来自后端任务快照，不重新放回占据整页的任务中心。
- 搜索模式、资源部位、预览尺寸、主题、提取范围和包格式复用 `ThemedSelect`。保持主题变量、浮层边界、键盘操作及空选项语义。Radix 的隐藏表单元素不等于可见原生下拉控件。
- 图片对比两侧各使用 `PanZoomImage`：滚轮围绕指针缩放、按住拖动、双击复位；Home/0 复位、加减缩放、方向键平移。两侧状态独立，换图和重开复位，释放 wheel 监听和 pointer 状态；这些操作只改变显示，不修改图片或应用 Mod。
- 总览主入口优先“安装 APX 插件”，顺序是安装 APX、管理 Mod、按需提取原图。点击先进入渠道和版本适配页，不能跳过安装确认。APX 是 Mod 所依赖的补丁；辅助资产插件是可选的提取工具，两者不能混淆。
- 总览的 APMM/APX 版本卡并排展示真实状态；APX 与渠道页共用 `plugin_status` 查询及失效通知，不新增一份可独立修改的安装状态。社交媒体在总览每行两项、全部常显；`SocialMedia` 的折叠实现只保留备用。
- 卡面默认按部位直接展开紧凑候选行。角色默认大卡片，另有独立横向紧凑卡，展示头像、名称和完整统计，点击进入皮肤/部位详情；不能用通用 ResourceList 展开所有角色部位。按分类记忆布局，两种角色模式分别保留滚动位置；旧角色 list 偏好迁为 compact，grid 保留。沿用当前风格，不机械复制旧界面。
- 角色首页按整名角色筛选：已应用为任一资源存在 activeHash 且未 disabled；有 Mod 为任一部位有候选，禁用候选仍计入；无 Mod 为整个角色都没有候选。先按完整实体判断，再用搜索和部位决定可见性，不能把资源过滤后再合并角色，否则混合角色会误入无 Mod，封面和统计也会被裁剪。其他分类保留既有分组身份和完整统计，状态仍逐资源判断。
- 角色紧凑卡取完整角色组中 item_icons 的 UT_Item_Hero_{id} 原图。缺图时使用占位图，切换卡片模式时分别挂载头像和封面，避免懒加载暂时沿用旧立绘。验收等待实际图片解码，同时确认中档卡高、每行数量和四档虚拟行不重叠。
- 详情继承页面的状态、部位、搜索和尺寸，逐资源筛选；空结果提供清除筛选。候选比较、管理、放大和应用保持独立，只有明确应用才发起写入；地块/鼠标整组操作仍使用完整配对数据。
- 列表与详情的同档候选必须共用实际边长和内部布局；原版、候选、添加与更多入口使用相同方形外框，不为详情另设放大倍数。验收比较真实 DOM 像素、字号和间距，并检查窄窗换行后的虚拟行高，不仅检查档位名称或偏好值。
- 页面新节点采用有界逐项入场，轮询复用节点不重播，虚拟列表只处理首批。切页、快速切换布局、卸载和减少动画时取消旧动画；基础样式始终可见。选中项有清晰的主题色边框，滚动条纤细且低对比，不用默认粗亮样式破坏布局。

定位：`src-ui/app/App.tsx`、`modules/SettingsPage.tsx`、`modules/OverviewPage.tsx`、`modules/OverviewVersions.tsx`、`modules/SocialMedia.tsx`、`modules/ResourcePage.tsx`、`modules/ResourceList.tsx`、`modules/ResourceGroupCard.tsx`、`core/domain/resourcePresentation.ts`、`modules/ResourceCandidateRow.tsx`、`modules/TaskPopover.tsx`、`hooks/usePageReveal.ts`、`hooks/useResourceLayout.ts`、`shared/ThemedSelect.tsx`、`shared/PanZoomImage.tsx`、`scrollbars.css`、`resource-list.css`。

## APX 平台目录隔离

`Settings.plugin_directories` 是按平台键保存的 `HashMap<String, PluginDirectories>`；JSON 名称为 `pluginDirectories`，每项有 `locallow`、`data`、`root` 三个可选路径。不能再使用一个全局路径控制所有渠道。

- `plugin_set_directory({platform, which, path})` 只更新目标平台的目标字段，不联动重写其他目录、其他平台或工作区 modimg。
- 旧 `pluginLocallowDir/pluginDataDir/pluginRootDir` 仅用于反序列化和兼容迁移：迁给原来选中的有效平台，缺省才用默认平台，保留已经保存的新字段。普通载入和保存不能反复复制到所有渠道。
- 状态检查、安装、还原、实际落点和打开目录都读取传入平台。未配置且无法唯一识别时提示选择，不能借用其他渠道的安装。
- 三行均在“更改”前放“智能匹配”。`plugin_match_directory({platform, which})` 只读探测已存在目录，不创建游戏目录、不保存配置。候选需用户点“使用此目录”，即使只有一个候选也保持可确认；多个安装不能默认取第一项。
- Steam 可以按对应 Data 名称查安装库。TapTap、哔哩哔哩、WeGame 使用同名 Data 文件夹，不能从文件夹名字猜渠道；先分别配置游戏根目录，再匹配当前渠道的 Data。Steam 国际服的仓库映射与本机目录隔离是不同规则，核对当前 `plugin_platform_info` 和安装分支。
- LocalLow 默认地址可能在多个渠道物理上相同，但各渠道的手动覆盖仍独立。辅助提取工具仅在工作区和所选渠道是同一安装时借用该渠道覆盖；路径无法确认相同就不传递。
- Android 不设置本机游戏目录，保留导出操作。独立“补丁缓存”卡片已移除，校验缓存仍由安装、还原、导出内部流程使用；不能把去掉卡片误做成删缓存机制。
- 前端目录组件按平台 key 重建，异步请求捕获操作时的平台，避免切换渠道后保存到另一个平台。安装状态根据文件摘要/校验结果判断，文件存在不等于补丁已安装。

定位：`src-tauri/src/apx_directories.rs`、`apx.rs`、`storage.rs`、`settings_commands.rs`、`auxiliary.rs`、`game.rs`；前端 `modules/ApxDirectories.tsx`、`modules/ApxPage.tsx`、`core/domain/apx.ts`。

## 资源、包与迁移

保留 `fullName`、`applicationSlot`、`groupKey`、每个 `ModFile.hash/path` 的不同职责。官方完整变体和同槽位多候选都保留；地块按同编号分组，鼠标按双状态分组，实际文件不合并。临时资源没有有效应用槽位，不能为了方便统一应用而猜槽位。

- 拖入优先级固定为文件名规则、明确部位落点、归属选择；全目录匹配不受页面状态、搜索或部位筛选限制。名称已有规则时，即使落点不同也不能覆盖规则。已知 PNG 直接提交，只有未知 PNG 进入归属步骤；APMod 保留独立包向导，仅支持 PNG/APMod。
- 拖入空部位的首个新候选自动应用，必须在库写入锁内复核；重复、已有候选和同批后续候选不替换，临时资源不应用。普通添加候选仍仅入库。定向副本名称使用 canonical.png，记录外部原名并保留独立 Vault 哈希路径；应用失败保留入库结果并显示原因。
- 原生拖入必须接通 enter/over/leave/drop 与物理坐标，按当前 DPR 转 CSS 坐标；显示窗口边框、明确部位高亮和实际目标提示。多资源实体卡不猜部位；取消、离开、提交、切页及卸载清理反馈，过期悬停响应不能恢复高亮。悬停匹配只解析名称，不完整解码或生成 Base64。
- 原生名称匹配完成前只显示匹配中，不暂时把文件标成落点归属。包括部位“添加候选”在内的对话框打开时，另一次拖入不得启动提交或叠加归属向导。

中文名称只能来自有证据的元数据；不要按数字 ID、术语表顺序或文件名直觉补猜。分类定义的生成源在 `config/sections.json`，不要只修改 Python 包里的生成副本。

旧 APMMOD01/02/03、无 storageName 的旧包、加密、缺卷、多包队列和同槽位独立 Vault 路径仍需兼容。导入“仅加入库”和“应用”是明确的用户选择；失败包不能污染下一个包的队列状态。

包导出及验收读取后台返回的 `path/volumes`，不要把请求的 `destination` 当作已经生成的文件。本轮导出实际产生 `sample.part001.apmod`，验收曾误用不存在的 `sample.apmod`；应先核对返回路径和文件存在性，再进入导入向导。

旧库迁移以 data 目录为源，复制后校验再提交，源只读，不自动重新应用到游戏。空库完整接续，非空目标仅按完整槽位和哈希补齐候选，保留现有应用、设置和预设；确认框展示全部旧候选与缺失数量。恢复记录和用户文件发生变化时不能强行覆盖。

- 排查迁移后替换失效时，用旧格式的合成库同时覆盖只按哈希存储和按目录存储的候选。先做复制迁移，再走界面共用的应用入口，核对首次应用、同槽替换、失败回滚的实际 modimg 文件摘要与 activeHash。迁移沿用旧的外部 modimgPath，玩家现场需核对它是否与当前启动的游戏渠道和目录一致。
- 原版缩略图只在对应 outimg 文件实际存在时显示定位按钮。兼容用户设置或游戏目录旁的旧 outimg，以及新版插件的本地提取目录。下载预览缓存与放大预览保持独立，定位前重新确认目标存在且位于允许的目录内。

定位：`src-tauri/src/workspace_catalog.rs`、`resource_rules.rs`、`resource_transaction.rs`、`packages.rs`、`migration.rs`、`migration_journal.rs`，以及工程 `docs/MIGRATION.md`。

## 工坊与无服务器作者流程

- 默认“加入库”不应用到游戏，应用是用户明确选择。预检展示新增、替换、删除和冲突，提交前复核其基础状态；不能拿过期预检直接写入。
- 搜索、分类、卡片/列表双视图与固定获取入口保持当前实现。相同版本的已安装作品不误标更新；离线、失败与空目录分别提示，封面下载不能串行阻塞整个列表。
- 用户没有服务器，正式主流程为本地草稿、导出投稿 ZIP、人工收稿、本机审核并生成静态签名目录；已有可选 HTTP 服务不作为启用条件。读取跨语言签名目录与真实包测试，不能只分别证明 Python/Rust 单元测试通过。
- 投稿 ZIP 可恢复到空白草稿；导出记录只写“已导出”，人工审核通过和远端发布完成分别记录。更新作品保留完整资源清单，漏选资源可能表示删除，必须在预检中明确。
- 文件展示名与存储身份分开，同名候选不覆盖；凭据保留系统凭据库/现有受控机制，不写入普通任务历史、公开包或日志。本地预检不因旧在线流程自动创建管理凭证。
- 本机维护者按 `workshop-service/README.md` 的 inspect、prepare、check-base 流程核对真实审核及作者身份依据。只有公共工坊产物进入发布，private 审核资料留在本机；准备不自动推送，不自动替用户向收稿渠道发送消息。
- UI 验收通过真实开关刷新状态；脚本直接改后端设置却未失效 React Query 时，先修正验收交互，不把界面旧缓存误判为产品流程失败。

定位：`src-tauri/src/author/`、`workshop/`、`src-ui/modules/author/`、`modules/workshop/`、`hooks/useAuthorDraft.ts`、`workshop-service/tools/`；定向验收入口见 [workflows.md](workflows.md)。
